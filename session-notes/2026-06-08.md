## AES Soil Profiles — OSD vs. SSURGO Mismatch

### Problem identified
App displays SSURGO component horizon data (aggregated representative values from chorizon table). Users comparing to NCSS site or UC Davis SoilWeb see OSD (Official Series Description) profiles — actual field-sampled pedons. These differ in horizon names, depth breaks, and property values.

### Root cause in code
- `aes-data.html:609`: `const dominantCokey = allHorizons?.[0]?.cokey;`
  — Takes first array element as dominant. Works because R orders by `comppct_r DESC`, but fragile.
- `build_all_profiles.R`: calls `fetchOSD()` but only for Munsell colors — profile structure (hzname, depths, properties) still all from SSURGO chorizon.

### Agreed fix approach
- Display OSD profile for the horizon diagram (matches SoilWeb)
- Link out to SSURGO/SoilWeb for full numeric properties — do NOT map SSURGO values onto OSD horizons (depth breaks differ; scientifically indefensible to depth-weight across mismatched boundaries)
- Show `compname` and `comppct_r` in popup so users understand which component is shown

### Pending work
- Rewrite `build_all_profiles.R`:
  - Identify dominant component per mukey (already first due to ORDER BY comppct_r DESC)
  - Fetch OSD only for dominant series
  - Output OSD horizon structure (hzname, top→hzdept_r, bottom→hzdepb_r, soil_color)
  - Fall back to SSURGO if OSD unavailable for a series
